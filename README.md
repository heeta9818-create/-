# 도배장이

도배 기사·사장님을 위한 **현장 일정 + 견적 관리** 웹앱.
현장에서 폰으로 쓰는 걸 전제로 만들었다.

## 지금 되는 것

- **로그인** — 이메일/비밀번호 가입·로그인, 카카오 로그인(설정 시), 사용자별 데이터 격리
- **현장 관리** — 고객·주소·평수·벽지·시공 예정일·진행 상태를 등록/수정/삭제
- **자동 견적** — 현장을 등록하면 물량과 금액이 바로 잡힌다
- **견적 계산기** — 평수 간이 산출 / 실측 산출, 단가·마진·부가세 조정
- **견적 이력** — 현장마다 1차·2차… 차수별로 저장, 직전 견적 값을 이어받아 다시 잡기
- **견적서 공유** — 고객이 로그인 없이 여는 링크를 만들어 카톡으로 전송
- **홈 대시보드** — 다가오는 시공 일정, 진행 중 현장 수, 계약 예정 금액
- **견적서 인쇄** — 현장 상세에서 바로 출력 (네비게이션 자동 제거)

## 바로 실행

```bash
npm install
npm run dev      # http://localhost:3000
```

Supabase 설정 없이도 그냥 돈다. 이때는 **로그인이 꺼진 개발 모드**로 뜨고
(고정된 개발용 계정), 데이터는 `.data/sites.json`에 쌓인다.

```bash
npm test         # 94개 — 견적 엔진, 폼 검증, 인증 가드, 사용자 격리, 견적 이력, 공유
npm run typecheck
npm run lint
npm run build
```

## 구조

```
src/lib/domain/     ← 도메인. 프레임워크 의존성 없는 순수 로직
  wallpaper.ts        벽지 롤 규격, 계수 기본값 (전부 여기 모여 있음)
  estimate.ts         물량·금액 산출 엔진
  estimate-schema.ts  견적 입력 검증 (저장 전 서버에서 다시 확인)
  public-estimate.ts  고객용 견적서 항목 재구성 (마진 숨김)
  saved-estimate.ts   저장된 견적 모델
  site.ts             현장 모델 + zod 검증
src/lib/auth/       ← 인증
  user.ts             현재 사용자 조회 / requireUser()
  dev-bypass.ts       로그인 우회 허용 여부 판단 (순수 함수)
  errors.ts           Supabase 영문 에러 → 한국어 문구
src/lib/data/       ← 저장소. 인터페이스 하나에 구현 두 개
  repository.ts       환경변수 보고 구현체를 고른다
  file-repo.ts        로컬 JSON (개발·데모용)
  supabase-repo.ts    Supabase (배포용)
src/app/            ← 화면 (Next.js App Router)
src/proxy.ts        ← 매 요청 Supabase 세션 갱신 (Next 16의 미들웨어)
supabase/migrations ← DB 스키마 (owner_id + RLS 포함)
```

**견적 엔진(`src/lib/domain/estimate.ts`)이 이 앱의 핵심이다.** UI 없이 단위 테스트로
검증되도록 순수 함수로 분리해 뒀다. 견적 로직을 손볼 때는 테스트부터 고칠 것.

## 견적 산출 방식

### 물량

두 가지 방식을 지원한다.

**실측 산출** — 방마다 가로·세로·천장고·개구부 개수를 넣는다.

```
벽면적    = Σ (2 × (가로 + 세로) × 천장고)
천장면적  = Σ (가로 × 세로)                      ← 천장 도배 시에만
개구부    = 문 개수 × 1.8m² + 창 개수 × 1.5m²
시공면적  = 벽 + 천장 − (개구부 × 공제율 0.5)
소요면적  = 시공면적 × (1 + 로스율)
롤 수     = ⌈소요면적 ÷ 롤당 면적⌉
```

개구부를 절반만 공제하는 게 기본값이다. 문·창 주변은 재단 로스가 크게 나서
전부 빼면 물량이 부족해지기 때문. `openingDeductionRate`로 조정한다.

**평수 간이 산출** — 실측 전 단계에서 쓴다.

```
전용면적 = 평수 × 3.3058 × (공급면적이면 × 0.75)
벽면적   = 전용면적 × 2.4
천장면적 = 전용면적 × 1.0
```

> "25평 아파트"는 보통 **공급면적**이고 도배 물량은 **전용면적** 기준이다.
> 이 구분을 놓치면 물량이 30% 넘게 틀어진다. 그래서 폼에서 기준을 반드시 받는다.

### 롤 규격 (국내 유통 표준)

| 벽지 | 폭 | 길이 | 롤당 면적 |
|---|---|---|---|
| 실크벽지 | 1.06m | 15.6m | 16.54m² |
| 광폭합지 | 0.93m | 17.75m | 16.51m² |
| 소폭합지 | 0.53m | 12.5m | 6.63m² |

### 금액

```
자재비   = 롤 수 × 롤 단가
부자재비 = 시공면적 × m²당 부자재비   (초배지·풀·퍼티)
인건비   = 품 수 × 일당               (품 = ⌈롤 수 ÷ 1인 하루 시공 롤 수⌉)
+ 추가 작업 (철거·곰팡이 처리 등), 출장비
+ 관리비·마진 (원가 합계 × 마진율)
− 할인
+ 부가세 10% (선택)
```

### ⚠️ 계수는 반드시 보정할 것

롤 규격은 표준값이라 그대로 써도 되지만, **로스율·평수 계수·전용률·1인 하루
시공량·일당은 출발점일 뿐이다.** 전부 `src/lib/domain/wallpaper.ts`의 `DEFAULTS`
한 곳에 모아 뒀다. 실제 현장 5~10건을 정산해 보고 본인 기준으로 맞춰야 견적이
맞아 들어간다.

## 견적 이력

현장마다 견적을 차수로 쌓는다. 현장 상세의 **견적 다시 잡기**로 들어가면
직전 견적 값이 채워진 계산기가 열리고, 고쳐서 저장하면 새 차수가 된다.

### 왜 계산 결과까지 저장하는가

저장할 때 **입력(input)과 계산 결과(result)를 둘 다** 남긴다.

입력만 저장하면 나중에 견적 엔진이나 `DEFAULTS`를 손볼 때 과거 견적 금액이
같이 바뀐다. 고객에게 이미 보낸 견적서가 나중에 다른 금액이 되는 건 있을 수
없는 일이다. 그래서 결과를 그 시점 그대로 박아 두고, 화면에서는 저장된 결과를
보여줄 뿐 다시 계산하지 않는다. 입력은 "이 값으로 다시 잡기"에만 쓴다.

### 금액은 서버가 다시 계산한다

계산기는 브라우저에서 돌지만, 저장 요청에는 **입력만** 실려 간다. 금액은
서버가 `calculateEstimate`로 다시 계산한 값을 쓴다. 브라우저가 보낸 합계를
그대로 믿으면 요청을 조작해 아무 금액이나 넣을 수 있다.
`estimate-schema.ts`가 그 입력이 상식적인 범위인지 먼저 확인한다.

### 차수는 삭제해도 재사용하지 않는다

`max(version) + 1`로 매기면 2차를 지운 뒤 저장한 견적이 다시 "2차"가 된다.
이미 보낸 "2차 견적"이 다른 견적을 가리키게 되므로, 현장마다 마지막 번호를
따로 들고 있다 (`sites.last_estimate_version`).

## 견적서 카톡 공유

저장된 견적서에서 **공유 링크 만들기** → 고객이 로그인 없이 여는 링크가 생긴다.
**카톡으로 보내기**를 누르면 기기의 공유 시트가 열리고 거기서 카카오톡을 고른다.

### 고객에게 보이는 것과 안 보이는 것

내부 견적서를 그대로 보내면 안 된다. 공개 화면(`/q/[token]`)은 다르게 묶는다.

| 내부 화면 | 고객 화면 |
|---|---|
| 실크벽지 자재비 + 부자재비 | **자재비** 한 줄로 합산 |
| 시공 인건비 + 관리비·마진 15% | **시공비** 한 줄로 합산 |
| 내부 메모 | 안 보임 |
| 면적·로스율 산출 근거 | 안 보임 |
| 추가 작업·출장비·할인 | 그대로 |

**합계는 같다.** 보여주는 방식만 바뀐다 (`public-estimate.ts`, 테스트로 고정).

합쳐진 금액에는 원래 단가 설명을 붙이지 않는다. "2품 × 250,000원"인데 금액이
684,917원이면 고객이 계산기를 두드리는 순간 어긋난다.

### 링크 다루기

- **링크를 아는 사람은 누구나 볼 수 있다.** 128비트 무작위 열쇠라 추측은
  불가능하지만, 전달받은 사람이 또 전달할 수는 있다
- 다시 눌러도 링크가 바뀌지 않는다 — 이미 보낸 링크가 죽으면 안 되니까
- **공유 중지**를 누르면 즉시 죽는다. 견적이나 현장을 지워도 죽는다
- 검색엔진에 걸리지 않도록 `noindex`

RLS 때문에 로그인 없이는 아무것도 못 읽는데, 공개 견적서는 읽혀야 한다.
테이블에 anon 읽기 정책을 여는 건 위험해서(조건을 잘못 쓰면 전부 샌다),
열쇠로 한 건만 꺼내는 `find_shared_estimate` 함수를 두고 그 함수만 anon에게
줬다. 돌려주는 컬럼도 명시적으로 골라서 메모·연락처·owner_id는 애초에
빠져나가지 않는다.

### 카카오 메시지 카드 (선택)

`NEXT_PUBLIC_KAKAO_JS_KEY`를 넣으면 공유 시트 대신 카카오 SDK로 카드 형태
메시지를 보낸다. Kakao Developers에서 JavaScript 키를 받고 도메인을 등록해야
한다. 비워 두면 공유 시트로 동작하므로 **설정 없이도 카톡 전송은 된다.**

> SDK 로드에 `integrity`를 비워 뒀다. 카카오가 버전별 SRI 해시를 개발자
> 문서에 공개하므로, 이 기능을 켤 때 해당 버전 해시를 함께 넣을 것.

## 로그인

**환경변수 유무가 모드를 결정한다.**

| | 로그인 | 데이터 | 용도 |
|---|---|---|---|
| Supabase 환경변수 **없음** | 꺼짐 (고정 개발 계정) | `.data/*.json` | 로컬 개발·데모 |
| Supabase 환경변수 **있음** | 켜짐 | Supabase (RLS) | 실사용 |

`requireUser()`가 로그인을 강제하고, 저장소의 모든 메서드가 `ownerId`를 받아
사용자별로 데이터를 가른다. Supabase 쪽은 RLS로도 막혀 있지만 쿼리에도
`owner_id` 조건을 남겨 뒀다 — 정책을 잘못 손대는 순간 조용히 새는 것보다 낫다.

**서버 액션은 UI를 거치지 않고 POST로 직접 호출될 수 있다.** 그래서 페이지에서
확인했더라도 `createSite`·`updateSite`·`deleteSite` 안에서 다시 `requireUser()`를
부른다.

### 프로덕션 안전장치

로그인이 꺼진 채로 배포되면 아무나 남의 현장을 보게 된다. 그래서
`NODE_ENV=production`인데 Supabase 환경변수가 없으면 **앱이 뜨지 않는다**
(보호된 페이지는 500, `/login`은 원인을 화면에 띄운다).

로컬에서 프로덕션 빌드를 확인할 때만 `ALLOW_INSECURE_DEV_AUTH=true`로 푼다.
실제 배포 환경에는 절대 넣지 말 것.

## Supabase 붙이기

1. Supabase 프로젝트를 만든다
2. SQL Editor에 `supabase/migrations/`의 파일을 번호 순서대로 실행
   (`0001_init.sql` → `0002_estimates.sql` → `0003_estimate_sharing.sql`)
3. `.env.example`을 `.env.local`로 복사하고 URL·anon key를 채운다
4. 서버 재시작 — 로그인과 클라우드 저장이 함께 켜진다

`repository.ts`가 환경변수 유무만 보고 구현체를 고르기 때문에 화면 코드는
건드릴 게 없다.

### 카카오 로그인 (선택)

기사님들에게는 이메일보다 카카오가 훨씬 편하다. 다만 외부 설정이 필요하다.

1. [Kakao Developers](https://developers.kakao.com)에서 앱을 만들고 REST API 키 발급
2. Supabase 대시보드 → Authentication → Providers → Kakao 활성화, 키 입력
3. 카카오 앱의 Redirect URI에 Supabase가 알려주는 콜백 주소 등록
4. `.env.local`에 `NEXT_PUBLIC_KAKAO_LOGIN=true`

설정 전까지는 버튼이 아예 안 보인다 (눌러도 안 되는 버튼을 두지 않으려고).

콜백은 `/auth/callback`이 받는다. 이메일 인증 링크도 같은 자리로 온다.

## 로드맵

우선순위 순.

1. **단가표 설정 화면** — `DEFAULTS`를 코드가 아니라 `/settings`에서 고치게
2. **견적 확정 표시** — 지금은 가장 최근 차수가 현장의 견적이다. 3차를 잡아
   놓고 2차로 계약하는 경우를 표현할 수 없다
3. **견적서 PDF** — 지금은 링크와 인쇄뿐이다. 파일로 첨부해야 할 때가 있다
4. **자재 발주 목록** — 현장별 롤 수를 모아 주간 발주표 생성
5. **입금·정산** — 계약금/잔금 입금 기록, 월별 매출 집계
6. **사진 기록** — 현장 시공 전/후 사진 (Supabase Storage)
7. **비밀번호 재설정** — 지금은 가입·로그인만 있다
